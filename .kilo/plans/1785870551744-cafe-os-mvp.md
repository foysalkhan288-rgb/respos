# Cafe OS Intelligence Agent — MVP Implementation Plan

**Plan ID**: `1785870551744-cafe-os-mvp`  
**Status**: Finalized  
**Scope**: FOH order processing, KDS dispatch, custom modifier validation, basic inventory deduction  
**Framework**: LangGraph + FastAPI + SQLite + OpenRouter

---

## 1. Goal

Deliver a LangGraph-backed POS intelligence layer that accepts JSON orders via REST API, validates custom modifiers, dispatches to KDS, deducts inventory in real time, and returns a strict schema-compliant response to the POS terminal.

---

## 2. Architecture

```
POS Terminal
   │
   │  POST /api/v1/orders  (JSON payload)
   ▼
FastAPI Server
   │
   │  invoke LangGraph graph
   ▼
LangGraph Orchestrator
   │
   ├── Node: parse_order          → build structured order items
   ├── Node: validate_modifiers   → map custom tags → unit deductions
   ├── Node: calculate_totals     → subtotal, tax, discounts, total
   ├── Node: dispatch_kds         → emit KDS payload to kitchen
   └── Node: deduct_inventory     → subtract BOM units from stock
   │
   ▼
SQLite Database (orders, menu, inventory, modifiers, kds_orders)
In-Memory Session Cache (per-process, LangGraph state)
```

**LLM**: OpenRouter API (tool-calling model, e.g. `mistralai/mistral-7b-instruct` or `google/gemini-2.0-flash-exp:free` for cost efficiency).  
**Checkpointer**: `SqliteSaver` — persists LangGraph session state to `cafe_os_state.db`.  
**Payment**: Mocked in MVP. `payment_status = "pending"` by default; no real gateway integration.

## 3. Data Models (SQLite Schema)

### `menu_items`
- `id` TEXT PK
- `name` TEXT
- `category` TEXT
- `selling_price` REAL
- `packaging_cost` REAL
- `active` BOOLEAN DEFAULT 1

### `recipe_bom` (bill of materials)
- `id` TEXT PK
- `menu_item_id` TEXT FK → menu_items.id
- `ingredient_id` TEXT FK → inventory.id
- `unit_qty` REAL
- `unit` TEXT (e.g. "ml", "g", "pcs")

### `inventory`
- `id` TEXT PK
- `name` TEXT
- `unit` TEXT
- `current_stock` REAL
- `reorder_threshold` REAL DEFAULT 0
- `cost_per_unit` REAL DEFAULT 0

### `modifiers`
- `id` TEXT PK
- `keyword` TEXT (e.g. "oat milk", "extra shot")
- `ingredient_id` TEXT FK → inventory.id
- `unit_qty` REAL
- `unit` TEXT
- `price_delta` REAL DEFAULT 0

### `orders`
- `id` TEXT PK
- `counter_number` TEXT
- `table_number` TEXT NULL
- `customer_id` TEXT NULL
- `subtotal` REAL
- `tax` REAL
- `discount` REAL
- `total` REAL
- `payment_status` TEXT DEFAULT "pending"
- `payment_method` TEXT NULL
- `created_at` TEXT (ISO8601)

### `order_items`
- `id` TEXT PK
- `order_id` TEXT FK → orders.id
- `menu_item_id` TEXT FK → menu_items.id
- `quantity` INTEGER
- `unit_price` REAL
- `modifiers_json` TEXT (JSON array of modifier keywords applied)
- `special_instructions` TEXT

### `kds_orders`
- `id` TEXT PK
- `order_id` TEXT FK → orders.id
- `items_json` TEXT (structured payload for kitchen printer/display)
- `status` TEXT DEFAULT "pending"  (pending → preparing → ready → served)
- `dispatched_at` TEXT (ISO8601)

## 4. LangGraph Graph Definition

```
State: TypedDict
  - order_id: str | None
  - counter_number: str | None
  - items: list[dict] | None
  - modifiers: list[dict] | None
  - subtotal: float | None
  - tax: float | None
  - total: float | None
  - payment_status: str | None
  - kds_payload: dict | None
  - inventory_deltas: list[dict] | None
  - low_stock_alerts: list[str] | None
  - error: str | None

Edges (sequential):
  parse_order → validate_modifiers → calculate_totals → dispatch_kds → deduct_inventory → END

No conditional branching in MVP. All nodes run in order.
```

## 5. Tools Registered with LLM

| Tool Name | Purpose | Output Schema |
|---|---|---|
| `create_order` | Insert `orders` row, return `order_id` | `{order_id: str}` |
| `add_order_item` | Insert `order_items` row | `{item_id: str}` |
| `lookup_modifiers` | Map keywords → `modifiers` rows + price delta | `{matched: list[dict], unmatched: list[str]}` |
| `calculate_totals` | Deterministic: subtotal + tax - discount | `{subtotal, tax, total}` |
| `dispatch_kds` | Insert `kds_orders` row | `{kds_id: str, status: str}` |
| `deduct_inventory` | Subtract BOM + modifier units from `inventory.current_stock` | `{deltas: list[dict], alerts: list[str]}` |
| `get_menu_item` | Fetch menu item + BOM by ID | `{menu_item, bom: list}` |

**Rule**: The LLM may *call* these tools, but all monetary arithmetic and inventory math runs inside the tool functions — never in the LLM's text generation.

## 7. Modifier Validation Logic

1. LLM identifies modifier keywords from `special_instructions` and `modifiers` array.
2. LLM calls `lookup_modifiers(keywords=...)`.
3. Tool returns matched modifiers with exact `ingredient_id`, `unit_qty`, and `price_delta`.
4. **Unmatched keywords are flagged** — returned in `error` field, KDS badge shows "UNKNOWN MODIFIER" for barista review.
5. Matched modifiers are stored in `order_items.modifiers_json`.

**Guarantee**: Zero free-text deduction logic. Every modifier maps 1:1 to a DB row.

---

## 8. Inventory Deduction Logic

1. `deduct_inventory` receives `order_id`.
2. Fetch all `order_items` for the order.
3. For each item, fetch `recipe_bom` rows → accumulate unit quantities per `ingredient_id`.
4. Add modifier unit deltas from `order_items.modifiers_json`.
5. Update `inventory.current_stock` with exact subtraction.
6. If `current_stock < reorder_threshold` after deduction, append alert to response.
7. All math is float-precise, no rounding.

---

## 9. Validation & Guardrails

- **Zero approximation**: All totals use Python `Decimal` or float with explicit rounding (2 dp for currency).
- **Strict schema**: FastAPI response models enforce TypedDict/Pydantic schemas. LLM output is never passed raw to hardware.
- **Data security**: Customer contact details and payment tokens are never included in logs or KDS payloads.
- **State persistence**: LangGraph `SqliteSaver` checkpoints every node transition. On restart, the graph resumes from last checkpoint — no in-context state accumulation.

## 10. Implementation Order

1. **Scaffold project** — `pyproject.toml` with `fastapi`, `langgraph`, `langchain-openai` (or compatible OpenRouter client), `pydantic`, `aiosqlite`.
2. **Database layer** — `db.py`: connection setup, schema creation SQL, seed script with sample menu + inventory + modifiers.
3. **Tool functions** — `tools.py`: all 7 registered tools with deterministic logic.
4. **LangGraph graph** — `graph.py`: state definition, 5-node sequential graph, `SqliteSaver` checkpointer.
5. **FastAPI app** — `main.py`: `/api/v1/orders` endpoint, error handling, response schemas.
6. **Integration test** — `test_order_flow.py`: seed DB, POST an order with modifiers, assert response schema, assert inventory deducted, assert KDS row exists.
7. **Run & verify** — `uvicorn main:app --reload`, POST test orders via curl/HTTP client, inspect SQLite DB.

## 11. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| LLM generates malformed tool args | Use Pydantic tool schemas; LangGraph validates before execution |
| Modifier keyword ambiguity | Tool returns `unmatched` list; KDS shows "UNKNOWN" badge for human review |
| Float precision in inventory | Use Python `Decimal` for all stock math |
| LangGraph checkpoint file corruption | `SqliteSaver` uses WAL mode; include backup of state DB in EOD cron |
| OpenRouter rate limits | Cache menu/inventory lookups in memory; batch tool calls where possible |
